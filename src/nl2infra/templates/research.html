What counts as a pass?

  • Checkov: no violations from the enabled infrastructure security checks.
  • OPA / Conftest: no violations of the configured project policies.
  • Server dry-run: the Kubernetes API accepts the proposed objects without saving them.
  • Plan conformance: checked resource properties match the approved reference plan.

“Safety pass” combines the first three checks. “All four checks” also requires plan conformance. Passing these checks does not establish runtime application health.

How to interpret the comparison

  • The arms use the same model, temperature, and original validators. A shared reference plan is used for conformance scoring.
  • C also receives structured approved-resource details and generates per resource. The B-to-C comparison includes those differences as well as repair.
  • Benchmark approvals are automatic, guardrails are evaluated separately, and benchmark runs do not open pull requests.
  • This is an incremental comparison. It does not isolate every factor or establish a general success rate.

Project-aware generation is a separate extension

The latest pipeline adds workload-specific fit checks. These historical results evaluate the original four checks and do not measure the project-aware extension.
